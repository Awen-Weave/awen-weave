## Grain enforcement at registration — phase 8, tasks 8.1–8.5 (2026-09-12, **0.2.21**)

- **THE RULE.** A predicate declares the finest grain its SOURCE supports (`PredicateDef.finest_grain`); a claim may be at that grain or **coarser, never finer**; a predicate registered with **no** grain is **refused — absent is not a wildcard**. Accepted by Huw as Llys 25/08/2026 `[sig:e61b92b3]` on `IDR-006 Awen/GRAIN-ENFORCEMENT-grammar-proposal-2026-08-19.md`; PHASES.yaml phase 8.
- **The value set is THREE, ruled by Huw as Llys 12/09/2026** (`RULING-to-199-seat-grain-value-set-2026-09-12.md`, `[sig:00fa9f13]`): `property` finer than `area` for spatial subjects, plus `not_spatial` for predicates whose subjects are not places (`event`, `tenancy`, `source`, `research_question` — 44 of the 143). `station` / `coastal_cell` subjects sit at the `property` end. The ORDER is defined over the spatial pair and is encoded as an order, not as interchangeable strings — **a fourth value is a ruling, not an edit**, which is why the enumeration and the entity-type map live in ONE module (`src/craidd/schema/grain.py`) and no caller holds a classification of its own.
- **Registry tier, not Tier-1 — verified, not assumed.** The constitution's qualifier key set is closed at 23 with `additionalProperties: false` (v0.1.7), so a per-CLAIM grain field would be a constitution change; grain sits on the PREDICATE, which is an open registry. `constitution_drift.py` runs clean against the pinned v0.1.7 after the change — **no re-vendor, no lockstep**.
- **Enforced ON THE REGISTRATION PATHS, not in a module a caller may skip** (task 8.5, the 26/07 lesson): `validate_predicate_def` (both refusals), the **import-time invariant** in `predicates.py` (`_assert_grain_declarations` — a predicate added straight into the module reaches no validator and is still refused), `craidd-init` (the only code path that writes a `predicate` row), and `validation_gate.grammar_violations` (the path EVERY snapshot builder on the estate takes). **Found and fixed in passing:** `validate_seed_predicates()` iterated the tuple bound into `validation.py` while `craidd-init` built its INSERT rows from the tuple bound into its own module — the same object only by coincidence of import order. It now takes the set it is asked about and `craidd-init` passes the very tuple it writes.
- **Two refusals at registration.** No grain; and a grain the predicate's own `applies_to_types` contradicts — an AREA-grain source that accepts `building` subjects is a standing permission to emit property-grain claims from an area-grain source, which is exactly the `alc-predictive-wales` fault, now caught at registration rather than at build.
- **Coarser stays legal and is tested** (task 8.4): a property-grain source rolled up to an `area` subject registers untouched. A guard that refused legitimate aggregation would break every roll-up in the estate and be deleted by the next person.
- **THE INTERIM, NAMED RATHER THAN IMPLIED.** All **143** registered predicates carry `Grain.UNDECLARED` until task 8.6 evidences each against its source. They are grandfathered by a frozen list (`INTERIM_UNDECLARED`) **pinned by digest so it can only ever shrink** — a new predicate cannot be waved through by adding a line. `undeclared_predicates()` reports what is outstanding, and the gate returns `finest_grain` in its `unchecked` tuple, so nobody can state the rule is fully enforced while 8.6 is owed. An undeclared grain is **unchecked, not refused**: every claim on the estate cites one of the 143 and every snapshot builder runs through that gate, so refusing would have hard-stopped every build between 8.5 and 8.6.

## S1 — Federation spine (2026-07-11, in working tree, not yet committed)
- **Deliverable A — snapshot builder** (`src/craidd/snapshot.py`): materialises a governed dataset into `snapshot-<iso>/{manifest,place-anchors,claims,stamps}.json`. Every record is `constitution.validate`-clean before anything is written; fail-loud with the full violation list and **no partial snapshot** on any invalid record. Deterministic output (sorted keys, stable ordering) so a committed snapshot diffs meaningfully.
- **Deliverable B — stamp emitter** (`src/craidd/gazetteer.py`): reuses the core `provenance_stamp` (no hand-rolled stamp) to emit one SCH-FEDERATION-001 stamp per federated read, plus `place_anchor()` (SCH-PLACEANCHOR-001) and `federated_name_claim()` (SCH-CLAIM-001 carrying `binding=federated` + `federated_from` + `source_ran_at`, derived from the same `SourceOfRecord` so stamp and claim can't drift). `source ran_at_utc` read from the source, never re-derived (verify-not-recall); `federated_utc` ≠ `ran_at_utc`.
- **`ran_at_utc` resolution order + self-declaring basis** (`src/craidd/ran_at.py`, reusable across every source): (1) the source's `run-manifest.json` `ran_at_utc` if it emits one → basis `run-manifest`; (2) else the source repo's **git HEAD commit time** (a real recorded source fact, verify-not-recall — not the builder's clock) → basis `git-head-commit`; (3) else **fail-loud**. The basis is declared in the stamp's `notes` free-text (`"ran_at_utc basis: …"`) so a Craffter can see whether the timestamp is authoritative or a proxy — no new Tier-1 property (SCH-FEDERATION-001 untouched). Git commit time can drift from actual build time, so an authoritative manifest is preferred once a source emits one.
- **Deliverable C — async request queue** (`src/craidd/queue.py`): the `requests/{inbox,claimed,done}` directory contract + the §6 request schema + a reader stub that lists/parses/validates inbox items; `claim()`/`mark_done()` lifecycle wired for S6.
- **Validation gate** (`src/craidd/validation_gate.py`): one `Validator` seam, two backends — `PorthValidator` (live MCP `constitution.validate`/`.version` on craidd `:8081`, the canonical build-time gate) and `SchemaValidator` (offline, vendored machine-layer schemas at `src/craidd/constitution_vendor/`, pinned tag). `default_gate()` prefers porth, falls back to offline. Manifest pins the **live** constitution version read from porth at build time (0.1.2), not a hardcode.
- **First target** (`src/craidd/readers/dolgellau.py` + `cli/craidd_snapshot.py`): the Dolgellau gazetteer reader materialises place-anchors from the Town Dataset buildings (UPRN + geometry + labels; `county_gss`=Gwynedd W06000002; ward/community/lsoa null until Lleolydd coverage). `craidd-snapshot dolgellau-gazetteer` runs it on craidd.
- **Proven live**: all three record kinds validate `valid=true` against live porth (constitution 0.1.2); a federated claim missing `source_ran_at` fails loud (confirmed against porth AND offline). Committed sample: `samples/dolgellau-gazetteer/snapshot-20260711T000000Z/` (3 anchors / 4 claims / 1 stamp, built from real craidd data, validated by live porth). 14 spine tests green (full suite 247 passed; the 2 `test_constitution_drift` failures are the pre-existing 0.1.0-pin vs local-0.1.2-tree gap, unrelated).
- **Delivery = committed-to-repo** (resolved 2026-07-11, not a static craidd endpoint for the first proof): `craidd-snapshot` writes straight into the tracked path `snapshots/dolgellau-gazetteer/<snapshot-id>/` (its `--out` default, computed from the running checkout — no external dir to copy in), pushed as `huw-awenweave`.
